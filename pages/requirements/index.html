    Requirements Specification¶

    📋 Functional Requirements (FR)¶

    The system requirements are categorized by functional area and tracked against project milestones:

    Requirement ID Specification Status
    FR-01 The system shall package and execute as a Chromium Manifest V3 browser extension. Implemented
    FR-02 The extension action click shall open the primary Meridian workspace in a browser tab. Implemented
    FR-03 The system shall accept arbitrary, non-empty user text for vectorization. Implemented
    FR-04 Semantic embedding inference shall execute within a dedicated background Web Worker. Implemented
    FR-05 The system shall generate a normalized 384-dimensional dense vector using MiniLM. Implemented
    FR-06 The model weights, tokenizer, and WASM binaries shall load from packaged local extension assets. Implemented
    FR-07 The system shall strictly prevent remote model downloads during runtime execution. Implemented
    FR-08 The interface shall display real-time inference lifecycle states (loading, ready, error). Implemented
    FR-09 The diagnostic view shall report vector dimensions, execution backend, latency, and vector norm. Implemented
    FR-10 The user shall be able to initiate explicit capture of an active browser tab. Planned
    FR-11 The system shall extract readable content from active webpages using DOM sanitization. Planned
    FR-12 Extraction shall preserve structured headings, paragraphs, code blocks, and data tables. Planned
    FR-13 The system shall provide a fallback extraction strategy when article extraction fails. Planned
    FR-14 The system shall detect duplicate captures of existing URLs and offer updates over duplicates. Planned
    FR-15 The user shall be able to choose between Lightweight Mode and Deep Focus Mode capture. Planned
    FR-16 Deep Focus Mode shall segment documents using token-based overlapping windows (256w / 50o). Planned
    FR-17 Chunks shall retain parent heading hierarchy, page indexes, and source URL metadata. Planned
    FR-18 The system shall compute item-level centroid vectors and chunk-level passage vectors. Planned
    FR-19 The system shall persist searchable records, chunks, and vectors in browser IndexedDB. Planned
    FR-20 The system shall store heavy screenshots and binary snapshots in Origin Private File System (OPFS). Planned
    FR-21 Saved research workspaces shall persist reliably across browser restarts and device reboots. Planned
    FR-22 The user shall be able to import local PDF documents into the workspace. Planned
    FR-23 Extracted PDF passages shall preserve respective page number references. Planned
    FR-24 The user shall be able to import local Markdown notes and documentation. Planned
    FR-25 The user shall be able to manually create and paste standalone code snippets. Planned
    FR-26 The system shall vectorize natural-language search queries using the local model. Planned
    FR-27 Search results shall be ranked against stored vectors using cosine similarity scoring. Planned
    FR-28 The search interface shall highlight the exact passage matching the query intent. Planned
    FR-29 Saved research items shall be rendered as interactive visual cards on a 2D spatial canvas. Planned
    FR-30 The canvas shall support smooth panning, multi-level zooming, zoom-to-fit, and card selection. Planned
    FR-31 Users shall be able to drag, pin, inspect, delete, and reopen original source tabs from cards. Planned
    FR-32 Pinned and manually repositioned cards shall remain fixed during layout updates. Planned
    FR-33 The user shall be able to trigger an explicit spatial map reorganization on demand. Planned
    FR-34 The system shall provide an accessible tabular list view as an alternative to the 2D canvas. Planned
    FR-35 The system shall display storage quota consumption and provide manual cleanup tools. Planned
    FR-36 Automated storage cleanup routines shall guarantee the protection of user-pinned assets. Planned
    FR-37 The system shall support versioned JSON workspace export and import. Planned
    FR-38 Export and import shall preserve all vector data, metadata, and 2D canvas coordinates. Planned
    FR-39 The system shall generate a self-contained, standalone HTML file to review workspaces offline. Planned

    🛡️ Non-Functional Requirements (NFR)¶

    1. Privacy & Data Sovereignty¶

    • All extracted prose, code, PDFs, vectors, and search queries must remain exclusively on the user's device.
    • Zero analytics, telemetry, or external network requests during inference.
    • No paid cloud AI subscriptions or API keys required.
    • Sanitized HTML exports must render captured scripts completely inert.

    2. Offline Autonomy¶

    • Full embedding generation, local search, and canvas navigation must operate without internet connectivity.
    • Bundled model and WASM binaries must be verified and self-contained within the extension archive.

    3. Client Performance & Responsiveness¶

    • Search Retrieval Latency (SRL): Target median latency \(\le 20 ext{ ms}\) across 200+ indexed artifacts.
    • Canvas Rendering Smoothness: Target \(\ge 55 ext{--}60 ext{ FPS}\) during continuous pan and zoom with 100+ visible nodes.
    • Tab Ingestion Latency: Target \(\le 1.5 ext{ s}\) per tab for DOM extraction, chunking, and embedding.

    4. Storage Optimization¶

    • Dense Float32 vectors must support SQ8 scalar quantization, targeting \(\ge 70\%\) storage space savings.
    • Heavy binary previews (screenshots) must reside in OPFS separate from IndexedDB structured records.
    • Automated 7-day LRU purge for unpinned previews.

    5. Architectural Reliability & Maintainability¶

    • Background services must be stateless and survive Chromium Manifest V3 service-worker suspensions.
    • Centralized TypeScript contracts (contracts.ts) must prevent schema drift between modules.
    • Checksum verification (assets.lock.json) ensures bit-for-bit reproducibility across team environments.

    🚫 Explicit Scope Boundaries & Constraints¶

    To ensure achievable milestone delivery within the academic schedule, the following features are explicitly out of initial scope:

    • Optical Character Recognition (OCR): Scanned image-only PDFs without text layers will display an informative warning.
    • Full Language AST Compilation: Code blocks are extracted as structured text with language tags; full semantic compiler AST analysis is deferred.
    • Continuous Clipboard Ingestion: Automatic background clipboard snooping is avoided for privacy and security reasons.
    • Dwell-Time Auto Capture: Automated tab saving based on viewing time is excluded to prevent workspace pollution.
    • WebGPU Acceleration: Deferred until browser WebGPU compatibility and cross-platform stability are verified.
